# TokenPak v1.21.0 Release Log

## Scope

This minor release adds facts-only timing and live in-flight visibility to the
proxy. Each request can persist its UTC start time, time to first upstream
byte, and stream duration through an additive monitor migration. Cleartext SSE
can also expose the latest provider-reported output-token count while a request
is active. The auth-gated, read-only `GET /inflight` endpoint returns those
facts and any projection already computed by the admission path; it contains
no estimator or time-remaining calculation and does not mutate a ledger.

The release also adds an opt-in, default-off session-economics decoration for
eligible non-streaming client responses. Decoration is applied to a separate
client-return copy, wrapped in a versioned marker, and scrubbed from echoed
assistant history before replay. Provider-bound bytes, provider response
bytes, and accounting inputs continue to use the original undecorated content.

Three integrity repairs complete the release scope: session-forecast coverage
targets, readiness cache keys, and corpus reads now retain their measured
semantics; downstream socket disconnects no longer enter synthetic 502 or
provider-failure accounting; and release-gate SQLite schema capture now
materializes isolated clean stores, includes the proxy monitor schema, and
does not inspect ambient user databases. The legacy stats snapshot also now
writes to TokenPak's product-owned vault state directory instead of a retired
private vault layout.

The version-bearing candidate is prepared here. Its immutable commit identity,
candidate-wide validation, and independent acceptance remain pending.

## User-visible behavior

- `GET /inflight` lists active request identifiers, models, start times,
  elapsed milliseconds, observed time to first byte, and live output-token
  counts. When admission already produced token or cost projections, the
  endpoint returns those stored values without recomputing them.
- Live output-token updates apply to cleartext SSE. Compressed SSE keeps its
  existing persisted end-of-stream usage path but does not expose a live
  incremental value.
- Client-return session-economics decoration is off by default. When enabled,
  it applies only to eligible non-streaming, non-error responses with an
  explicitly resolved session; other responses remain byte-unchanged.
- A downstream `BrokenPipeError` or `ConnectionResetError` records a structured
  client-disconnect outcome without incrementing provider-breaker,
  session-error, or compression-error accounting.
- The legacy stats snapshot uses TokenPak's product-owned vault state
  directory.

## Upgrade

```bash
python -m pip install --upgrade "tokenpak==1.21.0"
```

No manual configuration migration is required. Existing proxy monitor stores
gain nullable timing columns through the additive migration. The optional
client-return decoration remains disabled unless explicitly enabled.

## Known issues and limitations

- Live mid-stream output usage is limited to cleartext SSE. Compressed SSE
  preserves end-of-stream accounting but does not expose a live incremental
  count.
- Client-return session-economics decoration is intentionally limited to
  eligible non-streaming responses with an explicit session and remains off by
  default.
- Release validation is incomplete; the version-bearing candidate has not yet
  completed candidate-wide validation or independent acceptance.
