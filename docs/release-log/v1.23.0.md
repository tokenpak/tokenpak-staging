# TokenPak v1.23.0 Release Log

## Scope

This minor release adds a time-remaining forecast surface to the
session-economics contract: a new set of contract types and a per-cell
calibration module that scores wall-clock completion time from measured
`started_at`/time-to-first-byte/stream-duration/incremental-usage inputs,
using the same walk-forward calibration approach as the existing
token-budget forecast. The mechanism ships behind its existing default-off
master switch and an empty per-cell publication table — every
session-economics payload continues to serialize `time_forecast` as
`status: unavailable` in this release. No configuration or default change
is introduced by this release.

The release also corrects configuration, CLI, setup, troubleshooting,
compression, and Claude Code documentation that described the legacy
`TOKENPAK_COMPACT` flag and `compression.enabled` setting as a live master
switch for the default HTTP request path, when both are compatibility-only
there. Default HTTP request bodies are unchanged by this correction; Claude
Code request bytes remain byte-preserved.

The release also adds `--json` output to the `cost` command, bringing it in
line with its sibling summary commands (`savings`, `status`, `doctor`),
which already supported `--json`. This closes a documented CLI consistency
gap identified during this release's own pre-cut validation.

A repair round closed two further findings surfaced by this release's own
pre-publication validation: the quickstart guide's SDK Path section
documented a constructor and methods that do not exist in the shipped
package (raising a `TypeError` for anyone following it) and has been
rewritten to the real, execution-verified `ContextPack`/`PackBlock` API; and
35 delta-attributable strict-mypy errors in this release's own new/touched
session-economics and time-forecast-calibration files were fixed
(behavior-preserving type repairs, no weakening).

A fourth-cut correction makes release builds byte-reproducible: the release
workflow now pins its build toolchain (`build`, `setuptools`, `twine`) and
derives `SOURCE_DATE_EPOCH` from the commit being built rather than
wall-clock build time, and a new post-build normalization step pins sdist
tar-member and gzip-container timestamps to that same value (setuptools'
sdist command does not honor `SOURCE_DATE_EPOCH` on its own). This closes an
artifact-determinism gap an independent adversarial validation round found
in the third candidate cut's build path; it is a release-pipeline change
only and does not affect package runtime behavior.

Two development-toolchain dependency pins are refreshed: `ruff` and
`twine`.

The version-bearing candidate is prepared here. Its immutable commit
identity, candidate-wide validation, and independent acceptance remain
pending.

## Classification and compatibility

- **SemVer:** MINOR because the release adds a new, purely additive public
  API surface (the time-remaining forecast contract types and calibration
  module) and a new CLI flag on an existing command, while preserving
  existing routes, defaults, and public symbols. The time-forecast mechanism
  does not change any shipped default or runtime behavior. The
  release-pipeline reproducibility fix changes no shipped package surface.
- **Risk:** full-conservative because the accumulated delta crosses core
  session-economics contracts, shared proxy request handling, and public
  documentation.
- **Public API:** 4,715 symbols versus 4,698 in v1.22.0: 17 additions and
  zero removals. All additions are the new session-economics time-forecast
  contract types and calibration-module surface. `cost --json` is a CLI
  surface addition, not a public Python API symbol, and is not reflected in
  this count. The quickstart-fix, delta-mypy repair round, and the
  reproducible-builds pipeline change touched no public API symbols.
- **Compatibility ruling:** retain the additive exports in this candidate.
  No existing public symbol is removed or reclassified.
- **Breaking changes:** none identified.
- **Deprecations:** none introduced.

## User-visible behavior

- Session-economics payloads gain a `time_forecast` field in the contract
  schema. It continues to serialize as `status: unavailable` for every
  request in this release — the feature's master switch remains
  default-off and its per-cell publication table remains empty, matching
  the existing token-budget forecast's own activation-gate discipline.
- Documentation, CLI help, setup, and troubleshooting guidance for the
  legacy `TOKENPAK_COMPACT` flag and `compression.enabled` setting now
  matches the actual default HTTP request path (compatibility-only there);
  operators configuring explicit compaction-helper callers see unchanged
  behavior.
- `tokenpak cost --json` now emits a single JSON document mirroring the
  human-readable summary (section, period, measurement availability, spend,
  live proxy session info, configured budget status); composes with
  `--week`/`--month` and `--by-model`. `--json` and `--export-csv` are
  mutually exclusive at the parser. Human-readable `cost` output is
  unchanged.
- The quickstart guide's SDK Path now documents and demonstrates the actual
  shipped API (`ContextPack`/`PackBlock`/`compile()`), verified end-to-end
  in a fresh virtual environment. No package behavior changed; only the
  documentation was wrong.
- No user-visible package behavior changes from the reproducible-builds fix
  — it affects only how the published wheel/sdist are built in CI, so
  independent rebuilds of this exact commit produce byte-identical
  artifacts.

forecast mechanism is inert by default; no runtime behavior changes as a

## Known issues and limitations

- The time-remaining forecast mechanism remains governed by its existing
  default-off master switch and empty per-cell publication table; this
  release does not change either. Populating a per-cell entry or flipping
  the switch is separately gated and not authorized by this release.
- The local dashboard's landing-page layout and some empty-state messaging
  are pre-existing and scheduled for a design refresh in a coming release;
  neither is touched by this release's inputs.
- Release validation is incomplete; the version-bearing candidate has not
