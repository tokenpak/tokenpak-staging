# TokenPak v1.22.0 Release Log

## Scope

This minor release completes automatic context injection for OpenClaw/SDK
requests on non-byte-preserved routes. The call site that runs the
vault-injection stage on these routes landed previously but had no real
effect: it wrote to session accounting with an argument shape the current
writer rejects, and its adapter-detection fallback always resolved to a
no-op passthrough adapter regardless of the actual request. Both are fixed,
so declared route policy now reaches the request body the provider receives.

The release also fixes the proxy's vault-injection receipt: measured
injected-token counts and source names are now written to the live
per-server session that request accounting and `GET /stats` read, instead of
a compatibility global no live request path consults. `tokenpak status` now
reports real injection totals instead of zero across zero requests.

Five CI toolchain and SDK dependency pins are refreshed: `actions/setup-python`,
`actions/setup-node`, `pypa/gh-action-pypi-publish`, and the TypeScript SDK's
`axios` and `@types/node`.

The version-bearing candidate is prepared here. Its immutable commit identity,
candidate-wide validation, and independent acceptance remain pending.

## Classification and compatibility

- **SemVer:** MINOR because the release adds one additive Python export (an
  explicit test seam) while preserving existing routes, defaults, and public
  symbols, alongside a behavior-restoring fix that lets already-declared
  route policy take effect for the first time.
- **Risk:** full-conservative because the accumulated delta crosses shared
  proxy request handling, session accounting, and CI/release workflow inputs.
- **Public API:** 4,698 symbols versus 4,697 in v1.21.0: one addition and
  zero removals. The addition is
  `tokenpak.proxy.vault_bridge.set_vault_index_override`, an explicit
  substitution seam for the vault index that replaces in-place
  module-attribute monkeypatching in tests.
- **Compatibility ruling:** retain the additive export in this candidate. No
  existing public symbol is removed or reclassified.
- **Breaking changes:** none identified.
- **Deprecations:** none introduced.

## User-visible behavior

- Routes whose policy declares automatic context injection now actually
  receive injected content in the request body sent upstream, instead of a
  silent no-op. The existing default-off master switch for the feature is
  unchanged by this release.
- The proxy's injection receipt (measured token count and source names) is
  now visible through `GET /stats` and `tokenpak status` instead of always
  reading zero.
- A malformed injection-pipeline result degrades to a measured zero at the
  receipt boundary instead of raising.

## Upgrade

```bash
python -m pip install --upgrade "tokenpak==1.22.0"
```

No manual configuration migration is required. If a route's policy already
declared automatic context injection, upgrading changes that route's runtime
behavior from a silent no-op to active injection — review request-volume and
token-accounting expectations for those routes before upgrading.
