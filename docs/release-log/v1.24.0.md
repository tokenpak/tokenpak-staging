# TokenPak v1.24.0 Release Log

## Scope

This minor release restructures the served local dashboard around a
savings-led, seven-block information hierarchy: a savings hero, a combined
health status strip, a compression chart, a cache strip that separates
product-attributed from provider-level cache hit rate, a recent-requests
table, a mode/session breakdown, and quick actions. Backend support is
additive (new `GET /savings` and `GET /recent` endpoints, a new
`window_24h` field on two existing endpoints) and fails open when the
request log is unavailable.

The release publishes the first reviewed time-remaining forecast
calibration cell (`claude-sonnet-5` / unknown effort / streaming) into the
per-cell publication table added in the prior release. The mechanism
remains gated behind its existing default-off master switch; populating the
table makes the cell eligible, it does not change the shipped default.

The retry engine and its supporting types are now directly importable from
a new `tokenpak.core.retry` module; the previously documented import path
continues to work unchanged as a compatibility re-export. An internal
proxy-launcher module is relocated from `tokenpak.core.runtime.proxy` to
`tokenpak.proxy.bootstrap`; the externally documented compatibility import
path (`tokenpak.runtime.proxy`) is unaffected, and a lazy compatibility
shim at the exact old internal path keeps it importable too (resolved on
first attribute access, so it never eagerly imports the proxy layer) —
this closes the public-API-snapshot question this release's own
pre-cut review surfaced, without a declared removal.

A request-accounting fix stops a model-endpoint request sent with no body
from logging a spurious internal error after the response has already
reached the client; usage for such requests is now recorded normally. The
`dev` extra is expanded to pull in the serving-surface dependencies so a
plain development install can import, test, and strictly type-check the
proxy and dashboard subsystems.

A dependency-lockfile refresh closes several open security advisories:
`aiohttp`, `cryptography`, and `h2` (core runtime dependencies — the pinned
lockfile was stale, though a fresh unpinned resolve already picked up
patched releases) and `nltk` (optional `compression`/`llamaindex` extras
only; one nltk advisory, CVE-2026-81726, has no upstream fix yet and
remains open for anyone using those extras). Two npm lockfiles pick up
dev-tooling-only bumps (`browserslist`, `js-yaml`, and an incidental
`brace-expansion` bump), none of which reach either published package's
runtime dependency graph.

**A first candidate for this release was prepared and then withdrawn before
publication.** A full staging-validation walkthrough on that candidate
found that `tokenpak serve` silently ignored the configured port
(`~/.tpk/config.yaml`'s `port:` key) and the `TOKENPAK_PORT` environment
variable whenever the `--port` command-line flag was not also given,
instead of honoring them as documented. That defect was pre-existing on
the prior shipped version as well, not introduced by this release's
content, but it was newly confirmed and recorded during that walkthrough
and blocked the first candidate from proceeding. A fix was developed,
reviewed, and merged (see Fixed, below) before this candidate was
prepared; this candidate includes that fix and is the first candidate
proposed for publication.

Fourteen further merges (this release's own bandit-baseline, reproducible-
build-ownership, and strict-mypy typing work; a stale-test repair; two
release-log documentation finalizations for prior versions; and six
routine dependabot bumps) are internal or documentation-only, with no
changelog entry.

## Classification and compatibility

- **SemVer:** MINOR — every content change in this release is additive
  (new module, new calibration data, new endpoints/fields, two bug fixes, a
  dependency-extras expansion) or a same-object relocation behind an
  unaffected compatibility path, including the previously open internal
  `tokenpak.core.runtime.proxy` question, now closed by a lazy
  compatibility shim rather than a declared removal (see Public API,
  below). This release is versioned explicitly as `v1.24.0`, classified
  MINOR under this project's release-classification policy.
- **Risk:** full-conservative — the accumulated delta touches core proxy
  request handling, the CLI-adjacent contract surface, and the dashboard,
  in addition to public documentation.
- **Public API:** confirmed by a CI-parity regeneration on this candidate's
  own tree (see Release stages, below, for the exact result). All 13
  `tokenpak.core.runtime.proxy.*` symbols present in the v1.23.0 snapshot
  are expected to remain present, unchanged, in this candidate's
  regenerated snapshot — the lazy compatibility shim landed in #778
  resolves them on first access, so the release-gate snapshot check
  (`make release-gate-check`) is expected to pass clean with zero
  undeclared removals. The one navigation-entry change (the `proxy`
  submodule ceasing to be listed in `tokenpak.core.runtime`'s own
  `__all__`) is an expected, self-consistent consequence of the same
  relocation.
- **Compatibility ruling:** retain — no public symbol is removed relative
  to v1.23.0. The one navigation-entry change is internal bookkeeping (a
  submodule ceasing to be listed in its parent's `__all__`), not the loss
  of an importable name; the submodule `tokenpak.core.runtime.proxy` and
  all 13 of its names remain importable via the lazy shim.
- **Breaking changes:** none, pending confirmation on the exact candidate
  tree (see Public API, above).
- **Deprecations:** `tokenpak.core.runtime.proxy` now emits a
  `DeprecationWarning` on first access, directing callers to
  `tokenpak.proxy.bootstrap`; this is a new deprecation warning, not a
  removal.

## User-visible behavior

- The served dashboard (`/dashboard`) has a new layout: a top-of-page
  savings figure, one combined health signal in place of the previous
  status dot, a compression chart, a cache strip that no longer derives its
  headline number from proxy uptime, a recent-requests table, and the
  existing mode/session breakdown and quick actions. Client-side refresh
  interval changes from 30s to 5s and pauses while the browser tab is
  backgrounded.
- Session-economics payloads gain reviewed time-remaining data for one
  measured cell (`claude-sonnet-5`, unknown reasoning effort, streaming);
  every other cell continues to report no data available. The feature's
  master switch remains default-off.
- The retry engine is now directly importable from a shorter, discoverable
  module path (`tokenpak.core.retry`); the previously documented import
  path is unaffected.
- A model-endpoint request sent with no body no longer produces a spurious
  internal log entry; its usage is now recorded like any other request.
- `tokenpak serve` now honors the configured `port` (`~/.tpk/config.yaml`)
  and the `TOKENPAK_PORT` environment variable when `--port` is not given,
  instead of always binding the built-in default. Precedence: `--port`
  flag > `TOKENPAK_PORT` env var > config file `port` > built-in default.
- A plain development install (`pip install -e ".[dev]"`) now includes the
  dependencies needed to import and test the proxy and dashboard code
  paths, without a separate extras flag.
- No user-visible runtime behavior change from the dependency-lockfile
  refresh; it closes advisory exposure in pinned installs only.

## Upgrade

```bash
python -m pip install --upgrade "tokenpak==1.24.0"
```

No manual configuration migration is required. The new calibration data and
the retry/proxy-launcher relocations are inert with respect to runtime
behavior. Anyone who was relying on `tokenpak serve`'s previous
port-precedence defect (configured port silently ignored) will now see the
documented order honored instead — no other default changes result from
upgrading.

## Rollback

```bash
python -m pip install --upgrade "tokenpak==1.23.0"
```

No destructive state migration is introduced.

## Known issues and limitations

- One nltk security advisory, CVE-2026-81726, has no upstream-patched
  release as of this lockfile refresh. It affects only the optional
  `compression` and `llamaindex` extras (nltk is not part of the base
  install); it remains open and is not fixable by this or any version bump
  alone.
- Documentation content for `tokenpak cost --json` and the remaining
  `TOKENPAK_COMPACT` "master switch" wording in three public documentation
  pages (outside this repository) were carried forward as known issues in
  the v1.23.0 release log. This lane found no merged content in this
  release's own inputs addressing either item and did not independently
  verify their current status in the documentation repository; treat both
  as still open unless confirmed otherwise before publication.
- The local dashboard's landing-page layout and empty-state messaging,
  carried forward as an unaddressed item in the v1.23.0 release log, are
  restructured by this release (see Scope, above). This lane read the
  served dashboard template and its backend data sources against the
  savings-led information-hierarchy content and found every required
  element present; on that evidence this item is expected to retire with
  this release rather than carry forward again.
- The time-remaining forecast mechanism remains governed by its existing
  default-off master switch and now-partially-populated per-cell
  publication table; this release adds one cell's data but does not flip
  the switch. Populating further cells or flipping the switch is separately
  gated and not authorized by this release.
- 33 open Dependabot security advisories across the public and staging
  repositories (17 and 16 respectively, including one critical each) were
  recorded as a standing condition ahead of this release's cut and were not
  triaged against this release's content; none has an open pull request
  coupling it to this release.
